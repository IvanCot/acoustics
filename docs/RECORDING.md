# Протокол собственных записей

Гипотеза: в наших условиях короткие удары по выбранным деревянным и металлическим предметам различимы по акустическим признакам. Это не универсальный определитель материалов.

1. Возьмите 2–3 предмета каждого класса: дощечка, деревянный брусок, деревянная ложка; металлическая кружка, крышка, пластина. Запишите реальные материалы и ID предметов в отдельный журнал. Избегайте составных предметов и опасных объектов.
2. Поставьте один телефон на устойчивую подставку в 20 см от места удара. Сохраняйте комнату, поверхность опоры, ориентацию микрофона и ударник — например, карандаш. Удары мягкие, сопоставимые по силе. Уберите музыку, речь и шум вентилятора. Отключите шумоподавление и автоматическую регулировку, если устройство позволяет.
3. Один файл — один отдельный стук. Около 0,5 секунды тишины до удара и 1,5–2 секунды затухания после. Ориентир длительности файла 2,5–3 секунды. WAV предпочтителен, MP3 допустим. Не проговаривайте название класса: модель может научиться различать слова. Прослушайте первые файлы и проверьте отсутствие перегрузки.
4. Соберите ориентировочно 20 записей каждого класса: 12 train (s01 и s02, по 6), 3 val (s03), 3 test (s04), 2 demo (s05). Чередуйте классы внутри каждой сессии, иначе «металл» может совпасть с фоном другой комнаты. Технические пороги 4 train и 2 test на класс нужны для запуска кода, а не для статистически надёжного результата.
5. Разделите данные до обучения. Сессия — один сбор для обоих классов при одной установке оборудования. После перерыва заново поставьте микрофон и соберите другую сессию для test. Все фрагменты одного длинного исходного файла, дубли одного удара и их преобразования должны оставаться в одной выборке. Предпочтительны отдельные исходные файлы.
6. Если проверяете новые предметы, используйте в test целиком другие предметы. Например, board01 только train, board02 только test. Пересечение предметов между сессиями допустимо только для узкой проверки знакомых предметов в новой сессии; не называйте её обобщением на новые предметы.
7. Для детектора стука соберите отдельный класс `other`: разговор без ударов, музыку, вентилятор, шум комнаты, шуршание, ветер, тишину в корректном WAV. Сопоставляйте длительность, микрофон и громкость с положительными примерами, иначе модель выучит особенности записи. Пустой или повреждённый файл не является обучающим аудио.
8. Ориентир для `other`: минимум 20–30 разнообразных реальных записей от нескольких людей и источников; технический порог 4 train и 2 test недостаточен для оценки устойчивости. Отдельные дикторы, исходные записи и сессии целиком оставляйте для test. Смеси «речь + стук», хлопки, удары по другим материалам и тяжёлый шум проверяйте дополнительно; бинарный детектор не гарантирует отказ всем таким примерам.

Формат папок:

```text
data/train/wood/s01/board01_take01.wav
data/train/metal/s01/cup01_take01.wav
data/train/wood/s02/board01_take07.wav
data/train/metal/s02/cup01_take07.wav
data/train/other/s01/speech01.wav
data/train/other/s02/room_noise01.wav
data/val/wood/s03/board01_take13.wav
data/val/metal/s03/cup01_take13.wav
data/val/other/s03/room_noise02.wav
data/test/wood/s04/board02_take01.wav
data/test/metal/s04/cup02_take01.wav
data/test/other/s04/new_speaker01.wav
data/demo/wood/s05/board03_take01.wav
data/demo/metal/s05/lid03_take01.wav
data/demo/other/s05/new_noise01.wav
```

ID сессии: латиница нижнего регистра, цифры, `_` или `-`, до 40 символов. Один ID для обоих классов; он не может встречаться в разных выборках. Имя файла рекомендуется `objectID_takeNN.wav`; интерфейс сохраняет файл под хешем содержимого для безопасных имён. Самостоятельно скопированные файлы сохраняют свои имена. В журнале команды храните соответствие ID предмета и материала.

Копируйте файлы в папки и нажмите «Обновить с диска», либо добавляйте их через форму «Данные и обучение». `val`, `test` и `demo` не участвуют в обучении. Сейчас `val` зарезервирован для ручного анализа, а метрики считаются только на `test`. `demo` не участвует в количественной оценке; файлы из неё загружаются в «Анализ звука» на защите. Они помечаются как известные папке demo, но остаются не использованными моделью. Ещё более наглядно записать новый файл после фиксации модели.

Точные дубликаты и совпадающие нормализованные WAV обнаруживаются автоматически. MP3-перекодирования, обрезки, близкие дубли и неверно указанные сессии не всегда обнаружимы. Назначение сессий, предметов и отсутствие утечек по происхождению — ответственность команды.

После просмотра test не меняйте признаки и параметры на основании этого результата. Для итераций используйте отдельную валидацию внутри train с группировкой по сессиям/предметам; для финальной проверки соберите новый test. Повторный клик проверки той же модели воспроизводит измерение, но не создаёт новые независимые данные.

В анализаторе по умолчанию включён каскад «1 → 2»: модель 1 проверяет всю запись на подходящий стук, модель 2 определяет материал только при пропуске. Переключатель «Только 2» пропускает детектор; используйте его для сравнения и заранее отобранных стуков. Тишина и сильная перегрузка отклоняются в обоих режимах. Для оценки выбирайте тот же режим: каскад оценивается по трём результатам (дерево / металл / неподходящий), модель 2 отдельно — только на настоящих стуках двух материалов.
