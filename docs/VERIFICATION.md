16 октября 2026 года. Использованы ECC `frontend-design-direction`, `make-interfaces-feel-better`, `click-path-audit`, `verification-loop`. Код запускается указанным пользователем Python `D:\anaconda3\envs\dl_gpu\python.exe`.

## Обновление: очередь файлов и индивидуальные результаты

Анализатор поддерживает множественный выбор и drop нескольких файлов. Каждый файл отправляется в `/api/analyze` отдельно после завершения предыдущего запроса. Таблица показывает имя, статус, результат/отказ/ошибку и кнопку просмотра графиков/аудио. На мобильном экране строки оформлены карточками без горизонтальной прокрутки. В память сохраняется ответ для каждой строки, повторный просмотр не отправляет файл заново. Анализ не изменяет train/test/demo.

Проверка в реальном браузере на изолированном сервере 8766 с синтетическими сигналами:

- Через FileList выбраны шесть записей: два разных сигнала с одинаковыми именами, неверное расширение, тишина, шум и повреждённый WAV. Четыре записи обработаны, у двух показаны индивидуальные ошибки; последняя запись обработана после ошибок.
- Инструментирование реальных `fetch` показало максимум один одновременный `/api/analyze`; события start/end чередуются. Один режим фиксируется на всю очередь. В каскаде шум отклонён, в прямом режиме он получает материал; тишина отклоняется в обоих.
- Во время обработки отключены выбор файлов, переключатель режима и кнопки просмотра. После завершения они доступны.
- Нативный клик по последней строке с повторяющимся именем открывает именно её ответ: active index 5, спектральный центр отличается от первой строки (2414 / 423 Гц). Фокус остаётся на кнопке, прокрутка списка сохраняется. При аудите исправлено пересоздание всей таблицы при выборе строки.
- Переключение режима возвращает те же файлы в очередь и очищает старые графики/аудио. Drop двух файлов заменяет выбор. Пакет только из ошибок не оставляет старый результат и плеер. Одиночный файл и его воспроизведение продолжают работать (readyState 4).
- Имя с HTML-разметкой отображается текстом: в таблице не появляется img. Ожидаемый HTTP 400 повреждённого WAV не останавливает очередь; необработанных JS-исключений в сценарии не было.
- Проверены 1440 px, 390 px и 320 px. На 320 px ширина документа 320 px; ширина и scrollWidth списка совпадают (246 px). На 390 px ширина документа 390 px, у списка 317 / 317 px. [Снимок мобильной таблицы](ui-evidence/batch-mobile-390.jpg).

`node --check web/app.js` — PASS. Python/backend в этой итерации не менялись; предыдущие 15 тестов здесь повторно не запускались. Сигналы и модели проверки хранятся только в `test-output/cascade-ui`; основная `data` остаётся пустой, качество реальных материалов не измерялось. Результаты очереди живут в памяти страницы и теряются при перезагрузке. Проверочный сервер после проверки остановлен.

## Обновление: две модели и переключение режима

Добавлены независимые детектор стука и классификатор материала, класс `other`, обучение каждой модели отдельно и переключатель «1 → 2 / Только 2». Детектор использует весь файл; модель материала — двухсекундное окно. При отказе детектора материал не вычисляется. Тишина и сильная перегрузка блокируют материал в обоих режимах, повреждённые файлы отклоняются до моделей.

Программные проверки: 15 unittest — PASS. Проверены отсутствие вызова второй модели при отказе, прямой обход первой, отсутствие обхода проверки тишины/перегрузки, независимая актуальность моделей, отсутствие влияния test на scaler/коэффициенты обеих моделей, конечные признаки тишины и учёт полного файла детектором. Проверка «все стуки отклонены» показывает ошибку каскада, а не искусственные 100% среди оставшихся. Проверка синтаксиса JavaScript и компиляция Python проходят.

В браузере на изолированном сервере 8766 и синтетических данных `test-output/cascade-ui` проверены: отдельное обучение моделей 1 и 2; прямой прогноз на шуме с отметкой «детектор пропущен»; блокировка каскада без обученного детектора; отказ шуму после обучения; отказ тишине; прохождение синтетического удара через оба этапа. В качестве браузерных файлов сигналы созданы в памяти: инструмент загрузки локальных файлов отказал из-за несовпадения собственных workspace roots. Основная папка `data` остаётся пустой. Проверены оба режима оценки: три итоговых класса и метрики детектора для каскада, два материала без отрицательных примеров для модели 2. На 1440 px и 390 px нет переполнения; на 320 px разделы анализа, данных и качества также не имеют горизонтальной прокрутки. Цели переключателя на мобильном экране — 58 px. Ошибок JavaScript в проверенном сценарии нет.

Синтетические проверки подтверждают программный маршрут, а не распознавание реальной речи/шума/материалов. Реальных обучающих записей и моделей в основном приложении пока нет. Физический микрофон не проверен. Прежние Lighthouse-отчёты и снимки ниже относятся к версии до добавления каскада; новый полный Lighthouse-аудит не выполнялся.

Новый [снимок анализатора с переключателем](ui-evidence/cascade-desktop.jpg) — 1440×1000, основное приложение без обученных моделей. После визуального просмотра исправлен контраст подписей radio на лаймовом фоне. Проверочный сервер остановлен; основное приложение остаётся на 8765.

## Сценарии кликов

Состояния: `state` — набор/модель/отчёт; `selectedFile` — входной файл; `lastResult` — текущий сигнал; `isBusy`, `recordingPending`, `recording` — блокировки операций.

| Действие | Проверенный переход |
|---|---|
| Добавление данных | Выбор класса/выборки/сессии → последовательная отправка файлов → реальные счётчики и журнал; неполный импорт сохраняет успешные файлы и перечисляет ошибки |
| Обучение | Только train → новая модель → старый прогноз сброшен, старый отчёт скрыт |
| Проверка | Зафиксированная модель → test → метрики, матрица и 4 строки результатов в изолированном тесте |
| Анализ без модели | Файл → фактические признаки/графики/аудио → прогноз отсутствует |
| Анализ с моделью | Новый файл → блокировка повторных операций → класс/баллы/графики/аудио |
| Неверный формат | Ошибка с ролью alert и разрешёнными форматами |
| Отказ микрофона | Объяснение и путь загрузки файла, кнопка снова доступна; отказ смоделирован в браузере |
| Смена файла/обучение/обновление данных | Старый результат очищается; пустые графики получают пояснение, старое аудио скрывается |

Для полного браузерного цикла использовался отдельный сервер на 8766 с `test-output/ui-dataset` и `test-output/ui-artifacts`. Все сигналы синтетические. Основные `data` и `artifacts/model.json` не заполнялись тестовыми обучающими примерами. Тестовый сервер после проверки остановлен.
