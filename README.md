# Акустический детектив

Веб-приложение для анализа звука удара: оно проверяет, похожа ли запись на стук, и оценивает, звучит ли предмет как дерево или металл.

**Демо:** [acoustic-detective.onrender.com](https://acoustic-detective.onrender.com/)

## Как провести демонстрацию

1. Откройте вкладку **«Анализ звука»** и выберите режим. **«С проверкой стука»** сначала отсекает речь, музыку и другие неподходящие звуки, а затем определяет материал. **«Только материал»** сразу выбирает между деревом и металлом.
2. Загрузите WAV или MP3 либо запишите короткий звук кнопкой микрофона. Несколько файлов обрабатываются по очереди, результат каждого показывается в таблице. Для записи с несколькими отдельными ударами включите **«Несколько стуков»** и оставляйте паузы между ударами.
3. Откройте подробности результата, чтобы прослушать обработанный фрагмент и посмотреть форму волны и спектрограмму.
4. Во вкладке **«Данные и обучение»** можно добавить записи, назначить им класс и выборку, а затем обучить детектор, классификатор материала или обе модели.
5. Во вкладке **«Проверка качества»** выберите режим и запустите оценку на отложенных test-записях. Там отображаются метрики, матрица ошибок и прогнозы отдельных файлов.

## Данные для обучения

Для классификатора материала нужны записи стуков по дереву и металлу. Для каскадного режима также нужны примеры **«Неподходящего звука»**: например, речь, музыка, шум комнаты или ветер. Добавляйте только исправные WAV/MP3 размером до 12 МБ; один файл может длиться до 10 секунд.

При добавлении каждой записи укажите выборку:

- **Обучение (`train`)** — используется для подгонки моделей.
- **Валидация (`val`)** — помогает оценивать промежуточные изменения.
- **Проверка (`test`)** — отложенные данные для итоговой оценки.
- **Вне оценки (`demo`)** — записи, которые не участвуют в обучении и расчёте метрик.

Указывайте ID сессии для каждого сбора записей. Чтобы проверка была полезной, собирайте test отдельно от train: меняйте сессию, а для проверки новых предметов оставляйте сами предметы вне обучения. Не используйте test для подбора настроек. Рекомендации по записи и разбиению приведены в [протоколе записи](docs/RECORDING.md).

При обучении каждая train-запись проходит одинаковую обработку и получает две дополнительные версии с небольшим изменением громкости и слабым шумом. Валидация и test не аугментируются и не участвуют в подгонке. Число исходных и аугментированных примеров отображается в приложении.

## Как устроены модели

Сигнал приводится к моно и частоте 16 кГц, проходит лёгкое шумоподавление, затем из него извлекаются акустические признаки. Модель 1 использует 42 спектральных и временных признака и отличает стук от неподходящего звука. Модель 2 анализирует фрагмент вокруг удара по 39 признакам, включая MFCC, спектр и затухание, и выбирает дерево или металл. Обе модели — логистические регрессии со стандартизацией признаков.

Оценки классов служат сравнением двух известных классов и не калиброваны как вероятности. На результат влияют предмет, точка и сила удара, микрофон и помещение. Метрики во вкладке проверки описывают только текущий test-набор; они не гарантируют качество на других предметах и условиях.

## Запуск на своём компьютере

Нужен Python 3.10 или новее. В PowerShell, Windows Terminal или командной строке:

```powershell
git clone https://github.com/IvanCot/acoustics.git
cd acoustics
python -m pip install -r requirements.txt
python server.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Для остановки сервера нажмите `Ctrl+C`. По умолчанию он доступен только на этом компьютере.

## Публичное демо и хранение данных

Демо размещено на Render. В нём доступны добавление записей, обучение моделей и проверка качества. Файлы и обученные модели сохраняются в файловой системе экземпляра Render; для этого сервиса постоянный диск не подключён, поэтому данные могут исчезнуть после перезапуска или нового развёртывания. В публичной версии загруженное аудио передаётся серверу для анализа и может быть сохранено в датасет, если его добавить через вкладку данных. Не загружайте конфиденциальные записи.

Экземпляр Render на бесплатном тарифе может засыпать при простое, поэтому первый запрос иногда выполняется с задержкой.

## Состав репозитория и источники

- `server.py` — HTTP-сервер и API.
- `acoustic/` — обработка аудио, признаки, обучение и оценка.
- `web/` — интерфейс приложения.
- `data/{train,val,test,demo}/` — подготовленные записи.
- `artifacts/` — сохранённые модели и отчёты.
- `docs/RECORDING.md` — рекомендации по сбору данных.
- `THIRD_PARTY.md` — источники, лицензии и подготовка сторонних записей.

Фоновые звуки ReaLISED отобраны и преобразованы для проекта; ручные записи дерева и металла сделаны командой. Сведения об источниках, лицензии и соответствии файлов приведены в [THIRD_PARTY.md](THIRD_PARTY.md).
