# Акустический детектив

Локальный MVP кейса 01 Обнинского хакатона: различаем **дерево / металл** по короткой записи стука. Гипотеза относится к выбранным предметам, комнате и способу записи. Проверяем её на собственных записях из других сессий.

## Запуск

В репозитории включены 154 подготовленных WAV (77 ручных стуков и 77
отрицательных примеров), обе обученные модели и сохранённые отчёты.
После установки зависимостей можно сразу анализировать файлы и воспроизвести
обучение. Источники и условия использования данных: [THIRD_PARTY.md](THIRD_PARTY.md).
Исходные многогигабайтные датасеты и кэши исключены через `.gitignore`.

На другом компьютере используйте Python 3.10+ из своего окружения:

```sh
git clone https://github.com/IvanCot/acoustics.git
cd acoustics
python -m pip install -r requirements.txt
python server.py
```

Команды ниже показывают путь к Python на машине разработки. `start.ps1`
также использует этот конкретный путь; на другом компьютере запускайте
`server.py` непосредственно своим интерпретатором.

В PowerShell из папки проекта:

```powershell
& 'D:\anaconda3\envs\dl_gpu\python.exe' -X utf8 server.py
```

Открыть [http://127.0.0.1:8765](http://127.0.0.1:8765). Остановка — Ctrl+C. Также доступен `./start.ps1`, если политика PowerShell разрешает скрипты. В текущем окружении зависимости уже установлены; ничего скачивать для запуска не нужно.

Установка при переносе в среду с тем же Python (поддерживается Python 3.10+):

```powershell
& 'D:\anaconda3\envs\dl_gpu\python.exe' -m pip install -r requirements.txt
```

Другой порт: `server.py --port 8766`. Изолированные данные: `--data-dir PATH --artifacts-dir PATH`. Сервер слушает только loopback. Мобильная вёрстка предусмотрена; открыть этот сервер с физического телефона по сети в текущей конфигурации нельзя. Для телефонных записей переносите WAV/MP3 на ноутбук. Публичный хостинг, авторизация, многопользовательский режим и HTTPS не входят в MVP.

## Законченный сценарий

1. В «Протоколе записи» прочитайте инструкцию. Ориентир: по 20 файлов на класс — 12 train, 3 val, 3 test и 2 demo, из разных сессий. [Подробный протокол](docs/RECORDING.md).
2. В «Данные и обучение» выберите материал, выборку и ID сессии, добавьте WAV/MP3. Или скопируйте файлы в `data/train/wood/s01/file.wav` и аналогичные папки. Нажмите «Обновить с диска».
3. Добавьте также «Неподходящий звук»: речь без стука, музыку, шум и тишину в корректном WAV. Для модели 1 нужны минимум 4 стука (дерево/металл вместе) и 4 отрицательных примера в train; для модели 2 — по 4 стука каждого материала. Это технические пороги, а не гарантия качества. Можно обучить обе модели или каждую отдельно.
4. В «Проверке качества» выберите каскад или только модель материала. Для каскада нужно по 2 test-файла дерева, металла и неподходящих звуков из других сессий; для модели 2 — по 2 файла дерева и металла. Отчёт включает итоговую матрицу, accuracy, balanced accuracy, macro F1, список ошибок и JSON. Для каскада отдельно показаны пропуски неподходящих звуков, отказы настоящим стукам и точность материала среди принятых стуков с охватом.
5. В «Анализе звука» переключите режим: «1 → 2» сначала проверяет стук и только после пропуска определяет материал; «Только 2» сразу выдаёт материал без детектора. В прямом режиме речь и шум могут получить любой из двух классов. Пустой/повреждённый файл отклоняется до моделей; тишина и сильная перегрузка блокируют материал в обоих режимах. Интерфейс показывает этапы, некалиброванные баллы, графики и обработанное аудио. Без нужных обученных моделей прогноз не подставляется.
6. Для защиты оставьте 2–3 новых файла из отдельной сессии вне train/val/test. Можно хранить их в `demo`: эти записи исключены из обучения и количественной оценки. Отметка «уже есть в demo» означает знакомый набору файл, но не участие в обучении. Встроенная запись микрофона создаёт WAV до 3 секунд на localhost; нужен доступ браузера и реальный микрофон. Физический захват аудио требует проверки на вашем устройстве.

Для пакетного анализа выберите несколько файлов через Ctrl/Shift в диалоге загрузки или перетащите их вместе. Нажмите «Обработать N файлов»: запросы идут строго последовательно в выбранном режиме («1 → 2» или «Только 2»). Таблица «Файл → результат» показывает очередь, текущий файл, материал, отказ или индивидуальную ошибку. Неверный формат и повреждённый файл не прерывают остальные записи. Кнопка «Показать» открывает графики и обработанное аудио конкретной строки, в том числе при одинаковых именах файлов. На телефоне строки оформлены карточками. Анализ не добавляет файлы в обучающий набор; результаты хранятся в памяти страницы и очищаются при смене файлов/режима, обучении, обновлении данных или перезагрузке страницы.

## Архитектура и обработка

Четыре экрана: анализ, данные/обучение, качество, протокол. Русскоязычная адаптивная вёрстка, локальные CSS/JS, без CDN, npm-сборки и внешних шрифтов. Python HTTP-сервер из стандартной библиотеки выбран для однопользовательской локальной демонстрации: FastAPI/Streamlit в окружении отсутствовали, дополнительные серверные зависимости не нужны.

Визуальное направление по ECC: экспериментальный акустический прибор — графит, кислотный лайм, сигнальный оранжевый, плотная крупная типографика и геометрическая сигнатура образца. [Дизайн-контракт](docs/DESIGN.md), [снимки и проверка UI](docs/ui-evidence/report.json), [отчёт проверок](docs/VERIFICATION.md). Геометрия и техническая разметка декоративные; измерительные графики строятся только из фактического аудио.

```text
WAV / MP3 → проверка формата / тишины / перегрузки → моно → 16 кГц
 ├─ Модель 1: вся запись → 42 спектральных и временных признака
 │  → StandardScaler → LogisticRegression → балл стука ≥ 0.65?
 │    ├─ нет → отказ, материал не вычисляется
 │    └─ да → Модель 2
 └─ Режим «Только 2» → Модель 2 напрямую
Модель 2: начало события − 80 мс → 2 с → нормализация → 39 признаков
 → отдельный StandardScaler → LogisticRegression → дерево / металл
```

Одинаковая функция `acoustic/audio.py:process` применяется к train, test и новому файлу. Проверяются содержимое, расширение, размер до 12 МБ, длительность 0,15–10 с, 8–192 кГц, 1–8 каналов, конечные значения, тишина и сильный клиппинг. Модель 1 использует всю запись до обрезки: MFCC, centroid, flatness, ZCR (mean/std), длительность, исходную громкость, crest factor и статистики огибающей. Это позволяет учитывать длительный шум или речь за пределами двухсекундного окна материала. Модель 2 использует прежние 39 признаков стука. Оба scaler обучаются только на своих train-данных; C=0.5, class_weight=balanced. Фиксированный порог детектора 0.65 не подбирается по test и не является калибровкой. Детектор обучается различать «стук / неподходящее», а не ставить диагноз «речь» или «музыка». Неизвестные звуки и смесь речи со стуком могут пройти фильтр; это проверяется на данных.

MP3 декодируется libsndfile из soundfile. Здесь поддержка MPEG есть. Приложению ffmpeg не нужен; он используется только тестом для создания собственного MP3-файла. За пределами этого окружения проверьте поддержку MPEG в libsndfile.

`acoustic/experiment.py` хранит данные в папках, модель материала — `artifacts/model.json`, детектор — `artifacts/gate.json`, отчёт — JSON. Pickle не используется. Добавлен класс `other`: `data/{train,val,test,demo}/other/{session}/file.wav`. Проверяются пересечение сессий и дубликаты исходного/нормализованного аудио. Модель материала связывается только с train дерева/металла, детектор — со всеми train. Изменение отрицательных train-примеров делает устаревшим только детектор; прямая модель материала остаётся доступна. Отчёт хранит режим и ID участвующих моделей, скрывается при изменении соответствующих данных/моделей. `val` не участвует в fit и метриках и зарезервирован для ручной настройки; `demo` исключён из fit и метрик. Старая версия модели до двухэтапного анализа требует переобучения.

Данные сохраняются только при добавлении в выборку; отдельный файл «Анализа» обрабатывается в памяти и не сохраняется. Все запросы сериализуются для согласованного состояния. HTTP работает локально, отклоняет посторонние Host/Origin, разрешает только известные статические файлы и ограничивает тело запроса. Загруженные файлы не исполняются. Это локальный прототип, не сервер для публичного интернета.

## Проверка

```powershell
& 'D:\anaconda3\envs\dl_gpu\python.exe' -X utf8 -m unittest discover -s tests -v
```

Тесты используют **синтетические затухающие тоны только во временных каталогах**: проверяют обработку, реальное MP3-декодирование, цикл обучения/оценки, сохранение модели, отсутствие влияния test на scaler/коэффициенты, дубликаты, сессии, устаревание результатов, HTTP и плохие входы. Их результаты не являются точностью распознавания реальных материалов. Собственные данные изначально отсутствуют, искусственные результаты в интерфейс не подставляются.

Критерии завершения эксперимента: собственные train/test из независимых сессий, модель обучена, измеренное качество и ошибки показаны, 2–3 новых demo-записи проверены, ограничения объяснены. Программный путь можно проверить сейчас; эти экспериментальные критерии требуют ваших записей.

## Что показать за 2–3 минуты

- 30 секунд: выбранная гипотеза, два материала и разделение по сессиям.
- 60 секунд: 2–3 новых звука, прогнозы, сигнал/спектрограмма и известный материал.
- 45 секунд: test, размер выборки, матрица ошибок и честный реальный промах, если он есть.
- 15 секунд: зависимость от формы предмета, опоры, ударника, комнаты и микрофона; никакой диагностики неисправностей.

## Данные модели API и ограничения

[Исследование с первичными источниками и лицензиями](docs/RESEARCH.md): Greatest Hits (CC BY 4.0), RealImpact (лицензия ПО MIT; права на аудио отдельно не подтверждены), YAMNet и сравнение с Gemini API. Рекомендуется локальный базовый классификатор. Для первой модели добавлены 77 записей ReaLISED (CC BY 4.0): речь, телевизор, вода и пылесос. 53 используются в train, по 12 — в val и test; источники и параметры отбора — в `data/realised_negative_manifest.csv` и `data/REALISED_NEGATIVES_README.txt`. Отрицательные примеры выбраны по меткам, каждый файл отдельно не прослушан. Разница микрофонов и условий с ручными стуками может дать модели подсказку об источнике вместо типа события. Внешние API не используются.

Без собственных стуков и отрицательных примеров нельзя подтвердить качество моделей, обобщение на незнакомые предметы/комнаты, калибровку и устойчивость к речи/шуму. Точный/нормализованный хеш не выявляет все похожие дубли; происхождение сессий код проверить не может. В прямом режиме модель материала всегда выбирает между деревом и металлом; в каскаде детектор может ошибочно пропускать неизвестные звуки. Отказ стуку тоже считается ошибкой итогового каскада. Система не обнаруживает дефекты и не применяется к решениям о безопасности оборудования.

Для ручного разбиения по файлам `data/split_policy.json` явно перечисляет общие ID сессий в `file_split_sessions`. Их пересечение становится предупреждением, которое сохраняется в отчёте; дубликаты и ошибки аудио продолжают блокировать обучение. Такое качество относится к похожим условиям записи и не подтверждает перенос на независимые сессии.
